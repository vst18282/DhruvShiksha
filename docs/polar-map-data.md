# Polar Map demo data

The Polar Map is a frontend-only, offline-capable visualisation. Coordinates, climate snapshots, counts, expedition tracks and sea-ice shapes are illustrative demo data unless the source record says otherwise.

## Add a point

1. Add the point id to `PolarPointId` in `types/polar-map.ts`.
2. Add one `PolarPoint` to `POLAR_POINTS` in `data/polar-map.ts`.
3. Supply decimal-degree coordinates (`lat`, `lng`), one of the four point types, status, establishment year, copy, facts, counts, a 12-value climate sparkline, artwork and related links.
4. If the point should receive a connection from Goa, it is included automatically: `POLAR_ARCS` is derived from every point except `ncpor-goa`.
5. If it has a first-class station page, add that route to `links.overview`. A point does not need to be part of the core `StationSlug` type.

Marker types are not colour-only:

- `station`: circle (`●`)
- `headquarters`: diamond (`◆`)
- `historic`: square (`■`, dashed outline)
- `field-site`: triangle (`▲`)

The shared accessible table is generated from `POLAR_POINTS`, so no second list needs updating.

## Add a track

Existing expedition tracks live in `data/expeditions.ts` as `[longitude, latitude][]`. Add an expedition id to `TRACK_IDS` in `data/polar-map.ts` to expose its track on both renderers. To add a map-only track, append a typed `PolarTrack` directly to `POLAR_TRACKS` with:

```ts
{
  id: 'unique-id',
  name: 'Readable track name',
  region: 'antarctica',
  year: 2025,
  coordinates: [[73.81, 15.41], [18.42, -33.92], [11.73, -70.77]],
  color: '#5BB5E8',
}
```

Avoid a segment that jumps directly across the antimeridian. Insert a waypoint near `180°` and another near `-180°`, or split the route, to prevent a line across the map.

## Coastlines and projections

`lib/geo.ts` loads Natural Earth 1:110m land from the installed `world-atlas` package and converts it locally with `topojson-client`. The map never requests web tiles and never draws country borders. The 2D page uses Leaflet + React Leaflet and Proj4Leaflet for EPSG:3031 (Antarctic) and EPSG:3413 (Arctic); Himalaya and World use Web Mercator. The 3D page uses `react-globe.gl` with the same dissolved land geometry.

The sea-ice layer is generated by `seaIceFeatures(year)` in `lib/polar-map.ts`. It is an illustrative shape, not a measured product, and must retain its “demo” label unless replaced by vetted local GeoJSON.

## Shared state and links

`store/polar-map.ts` persists projection, year, layers and selected point under `pv-polar-map`. Register any future persisted map store in `store/rehydrate.ts`.

- 2D: `/tools/polar-map/2d?point=bharati`
- 3D: `/tools/polar-map/3d?point=bharati`
- `/map?view=3d&point=bharati` is a short compatibility URL and redirects to the 3D page.

Selection, year and layer settings survive switching between pages. The `point` query parameter takes precedence for a shared deep link.

## Validation

Run:

```powershell
npm run typecheck
npm run lint
npm test
npm run build
```

Then check both routes with network access disabled after the page chunks have loaded. There should be no requests to tile servers, geocoders or map APIs.
